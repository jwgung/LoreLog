# 0001. 서버를 Rust 라이브러리로 쓴다

- 상태: 채택 (2026-10-30)
- 결정한 사람: 사용자

## 맥락
서버(수집·일기·비서·사서)는 Python 표준 라이브러리로 쓰여 있었다. 사용자의 지시가 아니라 에이전트가 고른 언어다. PC 수집기는 같은 이유(설치, 백신, 교차 빌드)로 이미 Python에서 Rust로 다시 썼다.

이 시스템이 개인용(각자 PC에서 혼자 돌림)으로 갈지, 별도 서버로 갈지는 아직 정하지 않았다. Python 서버는 데스크톱 앱에 넣으려면 Python 런타임까지 묶어 배포해야 해서, 개인용으로 가는 길을 막는다.

## 결정
- 서버 전체를 Rust로 다시 쓴다. Python판은 같은 동작을 확인한 뒤 지운다.
- 서버 기능은 라이브러리 crate 하나(`server/`, `life-server`)에 둔다. 서버 실행 파일과 데스크톱 앱(Tauri)이 같은 라이브러리를 쓴다. 그래서 같은 코드가 집 서버로도, 데스크톱 앱 안에서도 돈다.
- 저장소 루트에 Cargo workspace를 두고 서버와 데스크톱 crate를 함께 넣는다.
- 외부 crate를 쓴다(HTTP 서버, SQLite FTS5, IMAP, 메일 해석 등). Python판의 "표준 라이브러리만" 규칙은 이어받지 않는다.
- 디스크 형식(원본 기록, 금고 노트, 설정 파일)과 HTTP API는 그대로 둔다. 두 판을 바꿔 끼워도 데이터와 앱이 이어진다. 사서 색인은 다시 만드는 사본이라 맞추지 않는다.

## 결과
- 개인용/별도 서버 결정을 미뤄도 된다. 개인용으로 가면 데스크톱 앱이 라이브러리를 직접 띄운다.
- 옮기는 동안 Python판이 실제 서비스를 계속 맡는다. 전환은 실제 데이터 사본으로 두 판의 결과를 비교한 뒤 한다.
- 원본 저장의 중복 거르기는 Python판과 달리 받은 줄의 글자가 아니라 해석한 기록으로 비교한다. Python판은 서버를 다시 띄운 뒤 다시 보낸 줄을, 보낸 쪽의 JSON 띄어쓰기가 Python 기본값과 다르면 알아보지 못했다.
