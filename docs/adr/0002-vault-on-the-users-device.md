# 0002. 금고는 사용자 기기에 산다

- 상태: 채택 (2026-10-30)
- 결정한 사람: 사용자
- 티켓: https://github.com/jwgung/LoreLog/issues/6

## 맥락
ADR 0001은 서버를 라이브러리로 써서 "개인용이냐 별도 서버냐"를 미뤘다. 이 시스템은 사람들이 알아서 설치해 쓰는 개인 도구다. 구상(「사서와 비서」)은 금고가 그 사람만의 것이고, 우리도 못 보고, 통째로 들고 나갈 수 있어야 한다고 정했다. 비슷한 제품들(Rewind, Humane)은 클라우드가 꺼지자 아무것도 남지 않았다.

## 결정
- **금고는 사용자 기기에 산다.** 데스크톱 앱이 서버 라이브러리(`life-server`)를 품는 것이 기본이다. 상시 서버(`life-ingest`, `life` 등 서버 실행 파일)는 늘 켜진 기계를 원하는 사람이 고르는 선택지다.
- **정본은 한 곳.** 다른 기기(폰, 다른 PC)는 그곳에 보내고 묻는 클라이언트다. 양방향 동기화는 하지 않는다. 옮길 때는 내보내기로 통째로 옮긴다.
- **망은 사용자가 따로 설치하는 Tailscale(또는 호환 도구).** 앱은 같은 tailnet 안의 주소만 받는다(토큰도 tailnet·loopback으로만 나간다). 앱 안에 망 기능을 넣는 것과 직접 운영하는 제어 서버는 나중이다.
- **모델은 사용자가 고른 주소**(OpenAI 호환). 우리가 모델을 제공할지는 정하지 않았다.
- **우리가 호스팅하는 금고는 하지 않는다.** "우리도 못 본다"를 지키면서 서버가 내용을 읽어 색인·대화를 할 방법이 없는 한.

## 결과
- 라이브러리는 어느 OS에서든 그대로 돌아야 한다. 라이브러리 안에 OS 전용 경로를 두지 않고(위치는 OS별로 고른다), 예약 실행(1시간마다 동기화 등)은 라이브러리가 아니라 그것을 띄우는 쪽(systemd 타이머, 데스크톱 앱)의 일이다. `life-server`가 Windows 대상으로 컴파일되는지 검증 때마다 본다.
- 받는 쪽이 꺼질 수 있다. 폰·PC 수집기는 닿지 않을 때 쌓아 두었다가 보내야 하고, 메일·일정은 켜질 때 따라잡는다.
- 금고가 한 곳에만 있으니 그 기계의 디스크가 단일 장애점이다. 백업은 따로 정한다(https://github.com/jwgung/LoreLog/issues/16).
- 만드는 사람 본인은 상시 서버를 쓴다. 제품의 기본과 별개다.
