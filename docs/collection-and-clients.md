# 수집 지도와 화면(클라이언트) 지도

이 시스템이 **어디서 무엇을 모아 서버의 어느 소스로 넣는지**, 그리고 **같은 화면을 어디어디서 쓰는지**를 한자리에 적는다.
기준: 2026-10-29. "지금 돌고 있음"은 이 리눅스 PC(gungbuntu)에서 확인한 실제 상태라 바뀔 수 있다 — 표의 상태 칸은 그때그때 다시 확인한다.

## 1. 수집 지도 — 어디서 → 무엇을 → 서버 소스

서버(gungbuntu)의 `life-ingest`가 받아 `~/.local/share/life/raw/<소스>/<날짜>.ndjson`에 쌓는다(원본, 안 지움).
파일 원본은 `raw/files/<sha256>`에 내용 해시 이름으로 보관(여러 채널이 같은 산출물을 알아보는 열쇠).

| 기기 | 무엇을 | 서버 소스 | 어떻게 |
|---|---|---|---|
| **폰 (LoreLog 앱)** | 앱 사용·위치·메신저 알림·음성(전사)·통화 녹음·캘린더 | `raw/lorelog/` | 앱이 서버 `/ingest/lorelog`로 NDJSON 전송. 민감 앱 제외, 일기 재료는 사용자가 허용한 메신저만 |
| **서버 자신 (gungbuntu)** | 메일(받은·보낸), 메일 첨부 원본, 캘린더 | `raw/mailfile/` + `raw/files/`, (메일 노트는 Obsidian 미러) | `life-sync.timer`가 1시간마다 `life sync` → 메일·`mail-files`·캘린더를 끌어옴 |
| **PC (Windows, life-desktop / life-agent)** | 앞 창 활동(앱·창 제목), 감시 폴더의 산출물 파일 | `raw/pc/`, `raw/pcfile/` + `raw/files/` | 창 활동은 `/ingest/pc`, 감시 폴더 파일은 `/ingest/file`(해시로 중복 생략). 창 제목만 보고 키·화면·파일 내용은 안 봄. 비밀번호 관리자·시크릿 창 제목은 가림(기본 켜짐) |

### 수집 원칙 (바뀌면 안 되는 것)
- 목적은 **한 일의 산출물을 미리 정한 구조 없이 원본 그대로 보관**하는 것. 효율·일하는 방식 분석이 아니다.
- 산출물이 본체, PC 활동은 보조, 오프라인 활동은 일기 대화로 들어온다.
- 수집 단계에서 시스템이 의미로 거르거나 접지 않는다. 통제권은 사용자에게(일시정지·앱 제외·범위 삭제·감시 폴더 직접 지정).
- 같은 산출물을 여러 채널(메일·창 제목·PC 파일)에서 잇는 열쇠는 **파일 내용 해시**.

## 2. 화면(클라이언트) 지도 — 비서 화면을 어디서 쓰나

대화·할 일·서랍·말하기(비서 화면)는 **각 앱이 가진다.** 웹으로 공개하지 않는다.

| 클라이언트 | 화면 | 코드 위치 | 비고 |
|---|---|---|---|
| **폰 (LoreLog 앱)** | 네이티브 화면(Compose) | `app/src/main/java/com/lorelog/`(`ChatScreen.kt`·`DiaryScreen.kt`·`TodosScreen.kt` 등) | |
| **데스크톱 앱 (Tauri)** | 앱에 **번들된 화면**(webview로 그림, 서버에서 당겨오지 않음) | `desktop/shell/ui/`(`index.html`=비서, `settings.html`=설정) | Tauri라 화면은 webview로 그리지만 "웹 클라이언트"는 아니다 — 앱이 품은 화면이고 브라우저로 안 열린다. 서버 주소·토큰은 앱 설정(`server_config` 커맨드)에서 받아 서버 API를 직접 호출 |

- **서버(`life-ingest`)는 이제 API만 제공한다. 어떤 비서 화면도 서빙하지 않는다**(2026-10-29 결정). 과거엔 `server/web/`를 `/`에서 내줬으나 걷어냈다.
- **웹은 나중에 설정·관리자용으로만** 만든다(로그인, 사용자 관리). 자리는 `server/web/`(지금은 비어 있고 README만).
- 그래서 비서 화면을 고치면 폰(Compose)과 데스크톱(`desktop/shell/ui/`)을 **각각** 고쳐야 한다. 공유 코드가 아니다.
